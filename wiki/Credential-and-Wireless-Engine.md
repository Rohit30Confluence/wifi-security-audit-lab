# Credential and Wireless Assessment Engine

This feature adds two guarded capabilities to the authorized Wi-Fi security assessment framework.

## Credential audit

The credential engine provides:

- Hydra as an online credential-audit backend.
- John the Ripper as an offline password-audit backend.
- Explicit authorization validation before execution.
- Bounded Hydra concurrency (1-16 threads).
- A dry-run default.
- Execution timeouts.
- Normalized execution results suitable for evidence/reporting.

The engine does not use a fallback authorization scope. An invalid, missing, or mismatched authorization reference blocks execution before the subprocess is started.

## Wireless radio capability

The wireless capability detector is intentionally a capability probe, not an attack engine. It reports:

- available wireless tools;
- detected wireless interfaces;
- supported interface modes;
- whether monitor mode is advertised;
- whether the environment is discovery-only or monitor-capable.

Frame injection is reported as unknown unless a future backend implements an explicit, authorized self-test. This avoids falsely claiming injection support from driver metadata alone.

### Android / NetHunter

Stock/rootless Android may expose only limited wireless functionality. Full NetHunter adds Wi-Fi injection through a device-specific/custom kernel. External USB radios are commonly required for monitor mode on Android devices.

The framework therefore treats radio capability as a runtime property:

1. detect the interface;
2. detect supported modes;
3. select a compatible backend;
4. require authorization before active assessment;
5. record capability and evidence.

No deauthentication, handshake capture, credential phishing, or injection traffic is generated by the capability detector.
